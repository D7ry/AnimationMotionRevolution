# AMR 애니메이션 및 비헤이비어 개발자 가이드

> **대상 독자:** 이 문서는 애니메이션 제작자와 비헤이비어(행동 그래프) 개발자를 위한 문서입니다. 이 Animation Motion Revolution(AMR) 포크가 실제로 구현하는 애니메이션 주석과 그래프 변수 규약을 설명합니다. 일반 사용자를 위한 설치 안내서는 아닙니다.

언어: [English](developer-guide.md) | [简体中文](developer-guide.zh-CN.md) | **한국어**

## 1. AMR이 제어하는 항목

AMR은 HKX 애니메이션에 포함된 주석을 읽고 다음 데이터로 해당 클립의 모션 데이터를 대체할 수 있습니다.

- `animmotion`: 누적 로컬 이동
- `animrotation`: 누적 요 회전
- `animwarp` / `animwarpend`: 액터의 현재 전투 대상을 향하도록 수평 `animmotion`을 구간별로 조절하는 선택 기능

비헤이비어 그래프가 애니메이션 기반 모션을 실제로 사용해야 합니다. 해당 비헤이비어/상태에서 애니메이션 기반 이동 및 회전 권한(`bAnimationDriven` 및/또는 `bAllowRotation`)을 올바르게 설정하십시오. 루트 모션을 무시하는 비헤이비어는 주석만 추가해도 액터를 움직이지 않습니다.

AMR은 `RE::Character` 인스턴스에 작동하므로 플레이어, NPC 및 지원되는 크리처가 같은 런타임 경로를 사용합니다. 단, 각 비헤이비어 프로젝트가 필요한 모션 데이터와 그래프 변수를 노출하고 사용해야 합니다.

## 2. 주석 형식과 공통 파서 규칙

hkanno 형식의 한 줄은 주석 타임스탬프와 주석 텍스트로 이루어집니다.

```text
0.500000 animmotion 0 100 0
0.500000 animrotation 45
0.200000 animwarp 0 1 60 300
0.750000 animwarpend
```

타임스탬프는 Havok이 별도로 저장하며 클립 시작부터의 초 단위입니다. 그 뒤의 텍스트를 AMR이 파싱합니다.

다음 제작 규칙을 따르십시오.

- 주석 이름은 대소문자를 구분하며 소문자여야 합니다. 정확히 `animmotion`, `animrotation`, `animwarp`, `animwarpend`를 사용하십시오.
- AMR 주석 이름 앞에 공백 문자를 넣지 마십시오.
- 값 사이에는 일반 ASCII 공백을 사용하십시오. 현재 파서는 `animmotion`과 `animrotation` 이름 뒤에 문자 그대로의 공백을 요구합니다. `animwarp`와 `animwarpend`는 탭도 허용하지만 이 차이에 의존하지 않는 것이 좋습니다.
- 숫자는 소수점 표기를 사용하는 유한 부동소수점 값이어야 합니다. 내부 숫자 파서는 과학적 표기법을 지원하지만 `NaN`과 무한대는 거부합니다.
- `animmotion` 및 `animrotation` 타임스탬프는 `[0, 클립 길이]` 범위 안에 두십시오. 워프 제어와 달리 모션 및 회전 타임스탬프는 자동으로 범위 안에 제한되지 않습니다.
- `animmotion` 및 `animrotation` 키에는 고유한 타임스탬프를 사용하십시오. 같은 시간의 중복 키 순서는 정의되어 있지 않습니다.
- 한 클립의 모든 `animmotion` 및 `animrotation` 키를 같은 Annotation Track에 배치하십시오. AMR은 유효한 모션 또는 회전 키가 하나라도 있는 첫 번째 Track만 사용하며 이후 Track의 모션/회전 키는 무시합니다.
- 워프 제어와 자동 전투 경계 이벤트는 모든 Annotation Track에서 검색합니다.

현재 파서는 유효한 `animmotion` 또는 `animrotation` 뒤의 추가 값을 무시합니다. 이는 구현상의 특성일 뿐 지원 문법으로 간주하지 마십시오. 반대로 `animwarp` 또는 `animwarpend`에 추가 인수가 있으면 잘못된 형식입니다.

잘못된 모션/회전 주석은 경고 없이 무시됩니다. 정확한 예약 워프 토큰을 사용했지만 형식이 잘못된 경우 로그에 기록되며 [명시적 제어와 실패 시 비활성화](#명시적-제어와-실패-시-비활성화)의 동작을 따릅니다.

## 3. `animmotion`: 누적 이동

### 문법

```text
animmotion <x> <y> <z>
```

세 값은 해당 주석 시간의 **누적 로컬 변위**입니다. 그 키에서 추가할 델타가 아닙니다.

- X: 좌우 이동
- Y: 전후 이동. 표준 Skyrim/ADSF 규약에서 양의 Y는 액터가 바라보는 방향
- Z: 수직 이동

값은 `animationdatasinglefile.txt`(ADSF)의 이동 규약과 같은 Skyrim 애니메이션/월드 단위 비율을 사용합니다. Havok 미터 단위가 아닙니다. 음수도 유효합니다.

예시:

```text
0.000000 animmotion 0 0 0
0.250000 animmotion 0 20 0
0.500000 animmotion 0 80 0
0.750000 animmotion 0 100 0
```

0.25초의 누적 Y 위치는 20입니다. 다음 키는 0.50초의 누적 Y가 80임을 뜻하므로 그 구간은 60단위를 이동합니다. AMR은 키 사이에서 각 성분을 선형 보간합니다.

### 시작 및 종료 키

권장 형식:

```text
0.000000 animmotion 0 0 0
<클립-길이> animmotion <최종-x> <최종-y> <최종-z>
```

- 첫 키가 0초보다 늦으면 AMR은 0초의 암시적 영 벡터에서 보간합니다.
- 0초 키가 0이 아니면 즉시 적용되는 누적 기준값이 됩니다. 이 값은 모션 워핑으로 조절되지 않으며 순간이동처럼 보일 수 있으므로 보통 `0 0 0`으로 시작하십시오.
- 마지막 키 이후에는 최종 누적값을 유지합니다. 마지막 사용자 모션 시간과 HKX 길이가 다르면 AMR이 경고를 기록합니다.
- `animmotion` 곡선의 끝은 선언된 HKX 길이와 다를 수 있으며, 동시에 모션 워핑 타임라인의 끝입니다.

유효한 `animmotion` 곡선이 있으면 해당 클립의 바닐라 이동 모션을 대체합니다. 없으면 AMR은 사용 가능한 바닐라 이동을 게임에 맡깁니다. 사용자 이동과 바닐라 이동이 모두 없으면 샘플 이동은 0입니다.

## 4. `animrotation`: 누적 요 회전

### 문법

```text
animrotation <요-각도>
```

`animrotation`은 수직 Z축 둘레의 누적 요를 정의합니다. 피치나 롤은 정의하지 않습니다. AMR은 각 값을 쿼터니언으로 변환하고 키 사이에서 게임의 쿼터니언 보간을 사용합니다. 음의 각도도 유효합니다.

한 바퀴 회전 예시:

```text
0.000000 animrotation 0
0.500000 animrotation 90
0.900000 animrotation 180
1.200000 animrotation 270
1.500000 animrotation 360
```

180도에 가깝거나 그보다 큰 회전에는 중간 키를 사용하십시오. `animrotation 360` 하나만 있으면 쿼터니언 방향이 0도와 같기 때문에 의도한 전체 회전 경로를 단독으로 표현할 수 없습니다.

이동과 마찬가지로 0에서 시작하고 최종 키를 클립 끝에 배치하는 것이 좋습니다. 유효한 사용자 회전 곡선은 클립의 바닐라 회전을 대체합니다. 없으면 사용 가능한 바닐라 회전을 유지하며, 둘 다 없으면 단위 회전을 사용합니다.

`animmotion`과 `animrotation`은 같은 Annotation Track에 섞어 넣을 수 있습니다. 모션 워핑은 `animrotation`을 절대 수정하지 않습니다.

## 5. `animwarp`와 `animwarpend`

모션 워핑은 한 구간의 X/Y 이동을 동일한 배율로 조절합니다. 모션을 새로 만들거나, 경로를 회전하거나, 액터를 대상으로 돌리거나, Z를 조절하거나, `animrotation`을 변경하지 않습니다. 따라서 유효한 `animmotion` 이동 곡선이 없는 클립은 AMR로 워핑할 수 없습니다.

### 문법

```text
animwarp <최소배율> <최대배율> [최대각도] [최대거리]
animwarpend
```

인수는 위치에 따라 해석됩니다.

- 최소배율: 허용되는 가장 낮은 X/Y 배율. 0 이상
- 최대배율: 허용되는 가장 높은 X/Y 배율. 최소배율 이상
- 최대각도: 선택 사항인 0–180도 방향 조건. 기본값 60
- 최대거리: 선택 사항인 액터-대상 수평 거리 상한. Skyrim 단위이며 0 이상. 기본값은 제한 없음

거리를 지정하려면 각도도 먼저 지정해야 합니다.

예시:

```text
animwarp 0 1
animwarp 0.25 1
animwarp 0 1.25
animwarp 0 1.5 60 300
animwarpend
```

`animwarp 0 1`은 완전 정지까지 축소할 수 있지만 연장은 허용하지 않습니다. 최대배율이 1보다 크면 연장이 가능합니다. 최소배율이 0보다 크면 액터가 전역 정지 거리 안에 있어도 완전히 멈추지 않습니다.

`animwarpend`는 해당 시간부터 이후의 유효한 `animwarp`까지 타임라인을 비활성 상태로 바꿉니다. `animwarp 1 1`은 유효한 선택적 각도나 거리 인수가 뒤따르더라도 정확히 같은 비활성 상태로 정규화됩니다. 잘못된 선택 값은 여전히 전체 주석을 잘못된 형식으로 만듭니다.

### 명시적 구간

각 유효한 제어는 자신의 시간부터 시작하는 반개구간을 소유합니다.

```text
[현재 제어 시간, 다음 제어 시간)
```

마지막 제어는 마지막 `animmotion` 시간에 끝납니다. 다음 제어의 정확한 시간은 새 구간에 속합니다. 한 게임 업데이트가 하나 이상의 경계를 지나면 AMR은 업데이트를 나누어 각 부분에 해당 구간 규칙을 적용하므로 한 프레임의 이동이 사라지거나 인위적인 정지가 생기지 않습니다.

예시:

```text
0.200000 animwarp 0 1 45 250
0.600000 animwarp 0.5 1.5 90 400
1.000000 animwarpend
1.400000 animwarp 0 1
```

결과:

- `[0.00, 0.20)`: 비활성
- `[0.20, 0.60)`: 배율 0–1, 45도, 250단위
- `[0.60, 1.00)`: 배율 0.5–1.5, 90도, 400단위
- `[1.00, 1.40)`: 비활성
- `[1.40, animmotion 끝)`: 배율 0–1

이동 곡선 범위 밖의 제어는 범위 안으로 제한되고 경고가 기록됩니다. 같은 타임스탬프에서는 Annotation Track 순회 중 마지막으로 만난 제어가 이깁니다. 이 순서는 이해하기 어려우므로 같은 시간의 제어를 피하십시오.

### 명시적 제어와 실패 시 비활성화

정확한 예약 `animwarp` 또는 `animwarpend` 토큰이 하나라도 있으면 형식의 유효 여부와 관계없이 전체 클립을 명시적으로 제어합니다.

- 전체 클립에서 암시적 공격 워핑이 억제됩니다.
- 첫 번째 유효한 `animwarp` 이전 구간은 비활성입니다.
- `animwarpend` 이후에는 다음 유효한 `animwarp`까지 비활성입니다.
- 유효한 명시적 구간은 액터가 공격 중이 아니어도 워핑할 수 있습니다.
- INI의 `bEnableForAttackAnimations`는 유효한 명시적 구간을 끄지 않습니다.

형식이 잘못된 정확한 제어는 구간 마커를 추가하지 않지만 기본 공격 워핑을 억제하고 `AnimationMotionRevolution.log`에 경고를 남깁니다. 오타 때문에 암시적 전투 동작이 뜻하지 않게 활성화되는 것을 막는 실패 시 비활성화 방식입니다.

다음 제어는 잘못된 형식입니다.

```text
animwarp -1 1
animwarp 1 0.5
animwarp 0
animwarp 0 1 181
animwarp 0 1 60 -1
animwarp 0 1 60 300 extra
animwarpend extra
```

## 6. 공격 애니메이션의 암시적 워핑

클립에 유효한 `animmotion`이 있고 예약 워프 제어가 하나도 없으며 INI에서 기본 공격 워핑을 켠 경우 AMR은 암시적 전투 구간을 만듭니다. 이 구간은 액터가 `IsAttacking()` 상태라고 보고할 때만 적용됩니다.

배포 기본값은 다음과 같습니다.

```text
0.000000 animwarp 0 1 60
```

실제 배율과 각도는 INI에서 가져옵니다. 암시적 워핑에는 최대거리 조건이 없습니다.

AMR은 모든 Annotation Track에서 다음 이벤트를 찾아 현재 암시적 구간을 끝내고 즉시 새 구간을 시작합니다.

- 대소문자를 구분하지 않는 정확한 `HitFrame`. `HitFrame.$payload` 같은 점 접미사를 허용
- 대소문자를 구분하지 않고 주석 텍스트가 `Collision_Add`로 시작하는 이벤트. 예: `Collision_Add.Node(WEAPON)`

두 경계 이벤트를 검사할 때 앞쪽 공백/탭은 무시합니다. `preHitFrame`, `NPCHitFrame`, `2_HitFrame`은 일치하지 않습니다. 현재 `Collision_Add` 검사는 단순 접두사 검사이므로 `Collision_Additional`도 일치합니다. 의도한 충돌 경계에만 이 접두사를 사용하십시오.

예시:

```text
0.000000 animmotion 0 0 0
0.700000 HitFrame
1.100000 Collision_Add.Node(WEAPON)
1.500000 animmotion 0 180 0
```

암시적 타임라인은 `[0, 0.7)`, `[0.7, 1.1)`, `[1.1, 1.5)`입니다. 각 구간에서 배율을 새로 계산하므로 연속 타격을 현재 대상에 각각 맞출 수 있습니다. 같은 시간 또는 `0.0001`초 이내의 경계는 하나로 합칩니다.

## 7. 워프 계산 및 대상 규칙

정상적으로 구간에 진입할 때 AMR은 두 정확한 경계의 누적 이동을 샘플링합니다.

```text
원본벡터 = animmotion(구간끝) - animmotion(구간시작)
원본거리 = lengthXY(원본벡터)
희망거리 = max(0, 대상수평거리 - fStopDistance)
요청배율 = 희망거리 / 원본거리
최종배율 = clamp(요청배율, 최소배율, 최대배율)
```

클립 활성화 시 경계 이동을 캐시하므로 계산은 상수 시간입니다. 대상 획득/변경, 거리 범위 재진입, 공격 상태 진입 등으로 구간 시작 이후에 워핑이 처음 유효해진 경우에는 현재 커서부터 같은 구간 끝까지의 **남은** 누적 벡터만 사용합니다.

다음 관련 조건을 모두 통과해야 워핑이 “적용”됩니다.

- 액터에게 해석 가능한 `currentCombatTarget`이 있음
- 대상이 살아 있음
- 액터와 대상이 같은 Cell에 있음
- 현재 수평 거리가 명시적 최대거리를 넘지 않음
- 남은 원본 수평 거리가 `fMinimumAuthoredDistance` 이상이고 0이 아님
- 원본 월드 공간 벡터와 대상 벡터의 각도가 제한값 이하임
- 암시적 구간에 한해 기본 공격 워핑이 켜져 있고 액터가 공격 중임

각도 조건은 **원본 모션 방향과 대상 방향**을 비교하며 액터가 바라보는 방향과 대상 방향을 비교하지 않습니다. 따라서 대상이 뒤에 있어도 구간의 원본 모션 역시 뒤로 이동하면 워핑될 수 있습니다. 반대로 AMR은 앞쪽 이동 구간을 회전시켜 뒤쪽 대상을 향하게 하지 않습니다.

액터와 대상의 수평 거리는 각 Reference Position으로 계산하며 충돌 캡슐 반지름을 빼지 않습니다. 원하는 간격을 유지하려면 `fStopDistance`를 사용하십시오.

계산된 배율은 같은 대상과 같은 구간에서 캐시됩니다. AMR은 움직이는 대상을 계속 추적하기 위해 매 프레임 배율을 다시 계산하지 않습니다. 대상 유효성, 같은 Cell, 최대거리, 암시적 공격 상태가 워핑을 비활성화할 수 있으며 조건이 다시 유효해지면 남은 모션으로 재계산합니다. 캐시된 배율이 활성인 동안에는 각도를 다시 검사하지 않습니다. 새 구간은 항상 재계산합니다.

구간 거리는 곡선을 따라 실제로 이동한 길이가 아니라 **순 변위**의 크기입니다. 구간 안의 모든 X/Y 증분에 같은 배율이 적용됩니다. 뒤로 이동한 뒤 앞으로 이동하는 애니메이션은 독립적으로 처리할 방향 전환 지점에 제어 경계를 추가하십시오. 큰 최대배율은 구간의 모든 수평 모션을 증폭하여 미끄러짐이나 부자연스럽게 빠른 돌진을 만들 수 있습니다.

## 8. 비헤이비어 그래프 변수

AMR은 비헤이비어 제작자를 위해 다음 불리언 그래프 변수를 제공합니다.

```text
AMR_IsAnimationWarpingEnabled
```

정확한 런타임 의미:

- `true`: 해당 액터의 활성 AMR 이동 클립 중 하나 이상에 모션 워핑이 현재 **실제로 적용**됨
- `false`: 해당 액터의 활성 AMR 이동 클립 중 적용 중인 워핑이 없음

“적용됨”은 “클립에 `animwarp`가 있음”보다 엄격합니다. 유효한 대상이 없거나, 조건을 통과하지 못하거나, 원본 모션이 부족하거나, `animwarpend` 비활성 구간이거나, 암시적 규칙이 꺼졌거나 공격 중이 아니거나, `animmotion`이 없으면 false입니다. 유효한 계산 결과가 우연히 배율 1로 제한되어도 true입니다.

AMR은 동시에 활성인 추적 클립을 합산하므로 워핑되지 않는 블렌드 클립이 워핑 중인 다른 클립의 true를 덮어쓰지 않습니다. 사용자 이동을 샘플링할 때 합산값을 다시 쓰고, 추적 클립이 비활성화될 때 값을 지우거나 다시 계산합니다.

배포본에는 다음 Behavior Data Injector 설정이 포함됩니다.

```text
Data/SKSE/Plugins/BehaviorDataInjector/AnimationMotionRevolution_BDI.json
```

동일한 JSON:

```json
[
  {
    "projectPath": "Actors",
    "type": "kBool",
    "name": "AMR_IsAnimationWarpingEnabled",
    "value": false
  }
]
```

`projectPath: "Actors"`는 Behavior Data Injector가 `Data/Meshes/Actors` 아래 비헤이비어 프로젝트에 false로 초기화된 변수를 재귀적으로 추가하도록 합니다. 호환되는 Behavior Data Injector와 해당 런타임에 필요한 지원을 설치하십시오. 이 JSON 주입에는 Nemesis 또는 Pandora 생성 작업이 필요하지 않습니다. 주입된 변수가 없어도 AMR 루트 모션과 워핑은 계속 실행되지만 비헤이비어 그래프가 이 사용자 변수를 안정적으로 읽을 수 없습니다.

## 9. 낭떠러지 보호

낭떠러지 보호는 INI로 제어하며 직접 활성화하는 주석은 없습니다. 모션 워핑 이후에 평가되며 다음 조건을 모두 충족하면 전후좌우 모든 수평 방향에 적용할 수 있습니다.

- 클립에 사용자 `animmotion` 이동이 있음
- `EdgeProtection.bEnableForAttackAnimations`가 true
- 액터가 `IsAttacking()` 상태라고 보고함
- 전체 `animmotion` 곡선의 모든 키에 유의미한 Z 값이 없음
- 현재 수평 프레임 이동이 `fMinimumHorizontalDelta` 이상

사용자 곡선에 0이 아닌 Z 키가 하나라도 있으면 그 클립 전체에서 낭떠러지 제한을 끕니다. 따라서 위쪽 점프나 앞-위쪽 점프는 원본 모션을 유지합니다. AMR은 이 판단에 바닐라 이동을 검사하지 않습니다.

조건을 충족한 프레임 이동에 대해 AMR은 다음 작업을 수행합니다.

1. 현재 워핑된 X/Y 이동 뒤의 액터 중심을 예측합니다.
2. 가능한 경우 액터의 Havok Character Controller 볼록 형상에서 수평 풋프린트 반지름을 얻습니다.
3. 의도한 이동 방향으로 탐사점을 예측 중심에서 Controller 경계까지 옮깁니다.
4. 액터의 충돌 그룹과 Character Controller Layer를 사용해 월드 Z축으로 수직 하향 레이를 쏩니다.
5. 지지면을 맞히지 못하면 해당 프레임의 X/Y 이동을 억제합니다.

차단된 이동은 누적하지 않고 소비하므로 다시 유효한 지면으로 돌아왔을 때 보정 점프가 발생하지 않습니다. Z는 그대로 유지됩니다. Havok World를 사용할 수 없으면 검사는 통과하는 방향으로 실패하여 모션을 막지 않습니다. 허용된 레이 히트는 무엇이든 지지면으로 간주하며 재질, 경사 또는 Navmesh 보행 가능 여부는 분류하지 않습니다.

## 10. 설정 기본값

`Data/SKSE/Plugins/AnimationMotionRevolution.ini`의 배포 기본값:

| Section/키 | 기본값 | 의미 |
| --- | ---: | --- |
| `MotionWarping.bEnableForAttackAnimations` | `true` | 암시적 전투 구간 활성화. 유효한 명시적 구간은 이 설정을 무시합니다. |
| `MotionWarping.fDefaultMinimumScale` | `0.0` | 암시적 X/Y 최소배율. |
| `MotionWarping.fDefaultMaximumScale` | `1.0` | 암시적 X/Y 최대배율. |
| `MotionWarping.fDefaultMaximumAngleDegrees` | `60.0` | 암시적 방향 조건. |
| `MotionWarping.fStopDistance` | `0.0` | 명시적/암시적 워핑 모두에 적용되는 전역 희망 수평 간격. |
| `MotionWarping.fMinimumAuthoredDistance` | `1.0` | 워핑에 필요한 최소 남은 원본 수평 거리. |
| `EdgeProtection.bEnableForAttackAnimations` | `true` | 공격 낭떠러지 보호 활성화. |
| `EdgeProtection.fRaycastStartHeight` | `50.0` | 예측 경계 위 레이 시작점의 Skyrim 단위 높이. |
| `EdgeProtection.fRaycastDownwardRange` | `200.0` | 높인 시작점에서 아래로 향하는 레이 길이. |
| `EdgeProtection.fMinimumHorizontalDelta` | `0.10` | 탐사를 실행할 최소 프레임 이동. |
| `EdgeProtection.bDebugDraw` | `true` | 선택적 TrueHUD 낭떠러지 시각화 허용. |

하향 범위를 늘리면 액터보다 더 아래에 있는 지지면도 인정하므로 낭떠러지를 밟고 떨어질 가능성이 커집니다. 너무 작게 설정하면 작은 높이 차이에서도 이동을 잘못 차단할 수 있습니다.

## 11. 선택적 TrueHUD 개발 시각화

TrueHUD 진단은 `AMR_ENABLE_TRUEHUD_DEBUG`로 컴파일한 빌드에만 존재합니다. 매크로를 끄면 AMR은 TrueHUD API 통합을 컴파일하거나 포함하지 않습니다. 두 시각화는 처음에 숨겨져 있으며 단축키는 게임플레이를 변경하지 않습니다.

- **Page Up:** 모션 워핑 스냅샷 전환
- **Page Down:** 낭떠러지 보호 탐사 표시 전환

명시적 구간이 활성화되거나 공격 워핑이 가능한 상태에서 암시적 구간이 활성화되면 워프 시각화가 월드 공간에 고정된 1초짜리 스냅샷을 그립니다. 이미 진행 중인 유효 구간이 대상, 공격, 각도 또는 거리 조건을 나중에 충족하여 처음 적용될 때 다시 그릴 수도 있습니다.

- 노란색: 전체 원본 구간 벡터
- 8단위 높인 청록색: 워핑이 적용될 때의 조절된 구간 예측
- `animwarpend` 같은 비활성 구간: 워프 스냅샷 없음

스냅샷은 그리는 순간의 액터 위치와 방향을 사용하며 이후 회전을 따라가지 않습니다. 줄어드는 남은 벡터가 아니라 전체 구간을 표시합니다.

낭떠러지 표시는 조건을 충족한 각 탐사마다 갱신됩니다. 노란색은 예측 중심에서 Controller 경계까지, 초록색은 지지면을 맞힌 레이, 빨간색은 빗나간 레이를 나타냅니다. 탐사 도형은 짧게 유지되어 연속 검사가 이어져 보입니다.

## 12. 전체 제작 예시

```text
# 타임스탬프    주석 텍스트
0.000000     animmotion 0 0 0
0.000000     animrotation 0
0.150000     animwarp 0 1.20 60 350
0.350000     animmotion 0 45 0
0.500000     animrotation 15
0.700000     animmotion 0 110 0
0.700000     animwarpend
1.000000     animmotion 0 135 0
1.000000     animrotation 0
```

- 이동과 회전은 누적값입니다.
- `[0, 0.15)`는 사용자 모션을 사용하지만 워핑하지 않습니다.
- `[0.15, 0.70)`는 대상 조건을 통과할 때 X/Y를 0%–120%로 조절할 수 있습니다.
- `[0.70, 1.00)`는 사용자 모션을 사용하지만 워핑하지 않습니다.
- Z와 원본 회전은 `animwarp`의 영향을 받지 않습니다.
- 이 클립에는 명시적 워프 제어가 있으므로 암시적 공격 구간을 적용하지 않습니다.

워프 제어 시간은 모션 키와 일치하지 않아도 됩니다. AMR은 정확한 제어 시간의 누적 이동을 보간하여 캐시합니다.

## 13. 제작자 체크리스트와 제한 사항

애니메이션을 배포하기 전에:

1. 비헤이비어가 애니메이션 기반 이동/회전을 사용하는지 확인하십시오.
2. 모든 `animmotion` 및 `animrotation` 키를 한 Annotation Track에 넣으십시오.
3. 소문자 이름, ASCII 공백, 유한한 값, 고유한 타임스탬프를 사용하십시오.
4. XYZ와 요를 누적값으로 취급하고 0에서 시작해 클립 끝에서 종료하십시오.
5. 큰 회전에는 중간 요 키를 추가하십시오.
6. 암시적 전투 워핑과 명시적 제어 중 하나를 선택하십시오. 정확한 예약 제어가 하나라도 있으면 암시적 모드는 꺼집니다.
7. 순 모션 방향이 달라지는 단계 사이에 워프 경계를 배치하십시오.
8. 명시적 워핑도 액터의 현재 전투 대상이 필요함을 기억하십시오.
9. 비헤이비어에서 `AMR_IsAnimationWarpingEnabled`를 읽는다면 Behavior Data Injector와 함께 배포 BDI JSON을 설치하십시오.
10. `AnimationMotionRevolution.log`에서 길이 불일치, 잘못된 워프 제어, 구간 요약 및 배율 진단을 확인하십시오.

중요 제한 사항:

- AMR은 바닐라 전용 루트 모션을 워핑하지 않습니다. 워핑에는 사용자 `animmotion`이 필요합니다.
- 워핑은 배율만 조절하며 회전, 대상 이동 예측 또는 움직이는 대상에 대한 매 프레임 재조절을 하지 않습니다.
- 거리는 충돌 표면 사이가 아니라 액터 Reference Position 사이로 계산합니다.
- 큰 허용 각도는 대상에 대해 횡방향이거나 심지어 반대 방향인 모션도 조절할 수 있습니다.
- 반전 경로는 구간의 순 변위로 평가되므로 의도적인 분할이 필요합니다.
- 낭떠러지 보호는 하향 물리 지지 검사이며 Navmesh 경로 탐색이 아닙니다.
- 여러 Track에 나뉜 모션/회전 키 또는 같은 시간의 중복 키는 현재 파서에서 신뢰할 수 있게 정의되지 않습니다.

원본 주석 규약은 [Animation Motion Revolution 모드 페이지](https://www.nexusmods.com/skyrimspecialedition/mods/50258)를 참고하십시오. 그래프 변수 주입 형식은 [Behavior Data Injector 설정 가이드](https://github.com/max-su-2019/BehaviorDataInjector/blob/master/doc/How%20to%20create%20BDI%20config%20files.md)를 참고하십시오.
